# CRM Ablation Report (§9)

Two apples-to-apples ablations on the **real sandboxed CodeExecCritic** (no mocked critic in any number, §3/§15). Treatment and control differ in EXACTLY one variable. Plots show **mean ± std** over seeds.

> **Honest framing (review pass).** These ablations test **operational** novelty against a corpus on a bounded integer test domain — fuzz-testing, not proof. The genealogy mechanism (H2) does **not** beat control on the easy recall domain even scaled to n=8; report this plainly. A consolidated, number-by-number account of every follow-up experiment is in [`docs/FINDINGS.md`](FINDINGS.md).

## 9.1 Genealogy ablation (tests H2)

![Genealogy ablation](assets/ablation_genealogy.png)

**Genealogy ablation (H2).** Over 8 seeds, the treatment arm (`mode=genealogy`, which conditions the proposer on WHY past conjectures failed and which survivors to build on) reached 4.88±1.96 cumulative certified-novel survivors, versus 6.88±2.57 for the control arm (`mode=control`, prior statements listed for dedup only, no reasons). The two arms are identical in proposer, model, topic, k, rounds, critic, budgets, and seed list — they differ in exactly one variable (the reasoned genealogy), so the gap isolates its value. On secondary metrics the treatment shows mean survivor significance 0.52 vs 0.53, survival rate 0.35 vs 0.46, and trivial rate 0.27 vs 0.26. Reading: the treatment does NOT beat the control here (it trails by 2.00 survivors on average) — reported honestly per §9.1. At this n the gap is not statistically significant (Welch p=0.126, Mann-Whitney p=0.134; see [`docs/findings/genealogy_scale.md`](findings/genealogy_scale.md)), the point estimate trends the wrong way, and the trivial-rate difference is a near-tie (Welch p=0.90) — so the H2 advantage is NOT established on the easy (recall) domain. The std shown is population std over seeds; with sample std (ddof=1) the bands are wider still. The one place genealogy helps is a freshly-defined sequence the model cannot recall (the sign of the delta flips to +1.33), but that result is also underpowered at n=3 — see [`docs/findings/hard_domain.md`](findings/hard_domain.md).

## 9.2 Significance ablation (reward-hack guard)

![Significance ablation](assets/ablation_significance.png)

**Significance ablation (reward-hack guard).** Over 5 seeds, the fraction of “survivors” judged trivial/vacuous by an INDEPENDENT automation check (a degenerate-impl probe that ignores the significance weights) was 0.15±0.07 with the critic ON versus 0.27±0.08 with it OFF. The arms differ in exactly one variable — whether trivial conjectures are suppressed (score 0, excluded) or whether any valid statement counts. Reading: turning the significance critic ON drops the trivial-survivor rate by 0.12 (from 0.27 to 0.15) — the reward-hack guard works. This independent oracle (`experiments/_indep_oracle.py`) shares no code with the significance gate (review finding #5): it uses a structurally-unrelated degenerate battery on a disjoint sampling subdomain, so the comparison is no longer tautological. Even with the guard ON it still flags ~15% of survivors as guess-closeable; the guard reduces independently-measured triviality but does not eliminate it.
